Project Aim

The aim was to design a practical digital manufacturing system that allows the workpiece discharge process to be validated before physical deployment and then monitored through a professional Siemens-inspired dashboard.

Problem Definition and Motivation

Traditional commissioning often takes place after mechanical installation, which means logic errors, sensor problems and sequencing issues may only be discovered late in the project. This can increase cost, delay deployment and create safety risks on the shop floor. At the same time, production systems often generate valuable data that is not displayed in a clear or useful format for operators and engineers.

Late Commissioning Errors

PLC sequence faults and incorrect actuator behaviour can be expensive to correct if discovered only after physical installation.

Limited Operator Visibility

Without a connected dashboard, operators may not have clear visibility of total counts, storage status, alarms or historical production trends.

Manual Reporting

Production summaries often require manual data collection. This project replaces manual recording with automated CSV, PDF and email-based reporting.

Virtual Commissioning Workflow

The virtual commissioning stage was the foundation of the project. The Festo Workpiece Discharge Station CAD model was used without changing its geometry. Instead, the model was enhanced by applying physics, joints, constraints, sensors, actuators and signal connections so that realistic behaviour could be tested in a simulated environment.

Stage 1

NX CAD Modelling and Physics Setup

Rigid bodies, collision bodies and mechanical constraints were configured in Siemens NX MCD. Fixed joints secured the machine frame, relative fixed joints grouped moving assemblies, and sliding joints represented horizontal, vertical, gripper and piston motion.

  • Horizontal motion: left, right and origin
  • Vertical motion: up and down
  • Gripper motion: open and close
  • Piston motion: extend and retract

Why it mattered

This allowed the model to behave like a real machine and helped validate whether the programmed PLC sequence could drive the simulated mechanical system safely and correctly.

Stage 2

Sensor and Actuator Configuration

Sensors were configured to detect pallet arrival, middle positioning, pallet exit, left storage count, right storage count and reset/sink behaviour. Actuator signals controlled the conveyor, horizontal axis, vertical axis, grippers and piston.

A structured naming convention was used for signals so that sensor feedback could be sent from NX to TIA Portal, while actuator commands could be sent from the PLC back to the simulation model.

Stage 3

TIA Portal PLC Program

The PLC program was developed using a modular architecture. OB1 calls separate function blocks for system setup, the workpiece station sequence and output interlocks. This approach keeps the logic readable, scalable and closer to industrial programming practice.

  • SystemSetup FB: handles start conditions, master enable and E-stop status.
  • WorkpieceStation FB: controls the full automatic SCL sequence.
  • OutputInterlocks FB: prevents conflicting motions and maps commands to outputs.

Automatic Sequence

The station detects the pallet, moves it to the centre, verifies position, picks the workpiece, selects left or right storage depending on availability, drops the workpiece, updates counters and returns to idle.

Stage 4

HMI Testing and Operator Interaction

A SIMATIC WinCC Runtime Advanced HMI was used to control and monitor the station during virtual commissioning. The HMI includes System ON, Start, Stop, Reset, sensor feedback, actuator feedback, storage counts, process status and alarm indication.

When both storage areas become full, the source is stopped and a critical alarm guides the operator to reset the process. Emergency stop conditions halt motion and generate clear alarm feedback.

Validation Outcome

The complete sequence was validated digitally using S7-PLCSIM Advanced, TIA Portal, WinCC Runtime Advanced and NX MCD before deployment.

Analysis and Reflection

Strengths

The main strength of the project is the complete workflow from virtual machine validation to real-time dashboard monitoring. It does not only simulate the system; it also converts machine data into useful operator information.

Limitations

The dashboard currently focuses on the most relevant production values rather than a full enterprise-level manufacturing execution system. Future work could add OEE, trend charts, cloud storage and predictive maintenance.

Lessons Learned

The project showed that successful automation is not only about writing PLC code. It also requires clear signal design, safe interlocks, realistic simulation, useful operator feedback and meaningful data presentation.

Future Development

The project can be extended into a more advanced smart factory platform by adding deeper analytics, predictive functions and wider system integration.

OEE Analytics

Calculate availability, performance and quality from live production data.

Cloud Connectivity
